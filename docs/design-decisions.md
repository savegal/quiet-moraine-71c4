# Интерфейс и данные

Пять скриншотов задали расположение экранов, характер кнопок и формат отчётов. В Proxima Soft для навигации используются символы `▣ ◇ ◈ ▤ ├ └ ✓ × ↻ ＋ ←`. Кнопка запуска зелёная, основной переход синий, отмена и остановка красные.

## Telegram

`sendRichMessage` рисует нативные компактные таблицы в карточках, отчётах, статистике и панели владельца. Отчёт по текстам содержит отдельные столбцы для успешных публикаций, попыток, конверсии, модерации и ожидания. Причины ошибок находятся в сворачиваемом блоке. Команда активации промокода копируется встроенной кнопкой Rich. [Форматирование Telegram Rich Messages](https://core.telegram.org/bots/api#rich-message-formatting-options)

Сервис карточек хранит ID последнего открытого сообщения для каждого чата и раз в пять секунд сверяет представление с последним сохранённым состоянием задачи. При изменении текста или действий он вызывает `editMessageText` с `rich_message` для Rich-карточки либо с `text` для обычной карточки. Обновления заканчиваются после финального статуса и окончания поздней проверки, если API её объявил. [Редактирование сообщений Telegram](https://core.telegram.org/bots/api#editmessagetext)

## Tokora и SQLite

- Запуск и расписание используют локальную очередь. Срок запуска сохраняется в той же записи, что и задание. Воркер сверяет разрешённые ID с полным составом папки через `GET /v1/accounts?folder=<id>` и проверяет наличие активных сессий. Если состав папки отличается или API недоступен, этот заказ ждёт повторной проверки, а другие подходящие заказы могут идти дальше.
- Перед отправкой сохраняются `accountFolder`, локальный список зарезервированных аккаунтов и `requestId`. Повтор запроса использует ту же папку и проходит новую сверку её состава. Общая проверка сессий запускается владельцем, а её карточка обновляется каждые пять секунд из `GET /v1/accounts/check`.
- Если к моменту повтора неопределённого запуска в выбранной владельцем папке появились аккаунты, бот резервирует исходный и текущий состав до подтверждения завершения. Один и тот же `requestId` может вернуть исходную задачу или создать её впервые с текущим составом папки.
- Владелец может настроить `settleMinutes` через экран настроек кабинета. Если при завершении API вернул `settleUntil`, бот продолжает читать состояние до контрольного запроса в конце окна. Время следующей проверки хранится в SQLite. Поздняя проверка уже завершённого заказа не занимает место в локальной очереди.
- Tokora запускает задачи по `accountFolder`. `assets.accountIds` используется в SQLite для проверки назначения и блокировки всего пула заказа. В запрос к Tokora это поле не отправляется. Папки заводятся в кабинете, по одной на трафера. Перемещать аккаунты между папками следует после завершения активных заказов. `GET /v1/accounts?task=<id>` показывает текущий состав папки, поэтому заказ с сайта с неизвестным составом на момент старта занимает очередь до завершения.
- Поддержка подтвердила 16 ноября 2026 года: у кабинета два общих места для задач, включая приостановленные. Импорт аккаунтов выполняется отдельно. `409 job_busy` не создаёт задачу у сервиса, поэтому бот сохраняет заказ в своей очереди. `409 job_duplicate` при первом запросе означает отказ, а при повторе неопределённого запуска требуется сверка. Бот освобождает пул после финального статуса с заполненным `finishedAt`; `stopRequested=true` само по себе только подтверждает запрос на остановку.
- Кнопка «Аккаунты задания» в карточке владельца показывает текущий список с `GET /v1/accounts?task=<id>` и отдельно числа `accountsAssigned` и `accountsWorking`. Список не используется как подтверждение исторического состава при запуске другого заказа.
- Владелец может выбрать папку для своих новых заказов через «Аккаунты → Папки Tokora». Участнику бот определяет папку по закреплённым аккаунтам. Настройка владельца не меняет ранее подтверждённые заказы.
- При неопределённом результате запуска воркер сохраняет `requestId` и ищет задачу по маркеру имени. Отзыв доступа удерживает повтор запуска, а чтение статуса продолжается. Если автоматической сверки недостаточно, решение принимает владелец в карточке заказа.
- Чтение задачи участником ограничено его Telegram ID. Карточка владельца проверяет `OWNER_ID`. Скрытие завершённого заказа убирает его из личного списка, оставляя запись в отчётности владельца.
- Telegram-обновления сохраняются в SQLite вместе с offset. Команды одного пользователя обрабатываются последовательно. Если процесс прерван во время внешней операции, проверь результат перед повтором.
- Пауза общей очереди доступна владельцу. Ответы API на управление и ручную проверку нормализуются перед обновлением статуса заказа.
- В панели владельца «Виды заказов» меняют доступ команды к новым заказам. Для видов без настроек в панели действует `RESTRICTED_MODES`. Доступ к ответам по ссылкам также управляет ответами на собранные комментарии и дозаказом ответов. Уже принятые заказы продолжают обрабатываться очередью.
- Загруженные фото включаются владельцем при проверке заказа. Для быстрого запуска используются настройки кабинета Tokora. Пакетное назначение берёт свободные активные аккаунты без переназначения чужого пула.
- При импорте с назначением в Telegram или CLI бот сначала проверяет cookies через `POST /v1/accounts/import/check`. Запись другого участника пропускается до обновления сессии. Если Tokora не определила UID и есть аккаунты других участников, бот пропускает запись и просит файл с cookies `multi_sids` и `sessionid`. Аккаунты назначаются по ID из ответа на поштучный импорт.
- Владелец может добавить один или несколько файлов через карточку получателя в Telegram. Предпросмотр хранит записи в памяти до подтверждения, а SQLite сохраняет итог, ID назначенных аккаунтов и статусы импорта. После перезапуска незавершённый импорт отмечается как прерванный. Для продолжения владелец загружает файл снова.
- Прокси с реквизитами импортируются через CLI на сервере. В Telegram сводка использует только статусы и идентификаторы. Для операций с общей очередью публикаций и общими материалами требуется доступ владельца.

Подробности полей и прав приведены в [Tokora OpenAPI](tokora-openapi.json).
