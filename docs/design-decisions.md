# Интерфейс и данные

Пять скриншотов задали расположение экранов, характер кнопок и формат отчётов. В Proxima Soft для навигации используются символы `▣ ◇ ◈ ▤ ├ └ ✓ × ↻ ＋ ←`. Кнопка запуска зелёная, основной переход синий, отмена и остановка красные.

## Telegram

`sendRichMessage` рисует нативные компактные таблицы в карточках, отчётах, статистике и панели владельца. Отчёт по текстам содержит отдельные столбцы для успешных публикаций, попыток, конверсии, модерации и ожидания. Причины ошибок находятся в сворачиваемом блоке. Команда активации промокода копируется встроенной кнопкой Rich. [Форматирование Telegram Rich Messages](https://core.telegram.org/bots/api#rich-message-formatting-options)

Сервис карточек хранит ID последнего открытого сообщения для каждого чата и раз в пять секунд сверяет представление с последним сохранённым состоянием задачи. При изменении текста или действий он вызывает `editMessageText` с `rich_message` для Rich-карточки либо с `text` для обычной карточки. После финального статуса подписка на обновления снимается. [Редактирование сообщений Telegram](https://core.telegram.org/bots/api#editmessagetext)

## Tokora и SQLite

- Запуск и расписание используют локальную очередь. Срок запуска сохраняется в той же записи, что и задание. Перед запросом воркер перепроверяет состояние, подписку и принадлежность назначенных аккаунтов.
- При неопределённом результате запуска воркер сохраняет `requestId` и ищет задачу по маркеру имени. Отзыв доступа удерживает повтор запуска, а чтение статуса продолжается. Если автоматической сверки недостаточно, решение принимает владелец в карточке заказа.
- Чтение задачи участником ограничено его Telegram ID. Карточка владельца проверяет `OWNER_ID`. Скрытие завершённого заказа убирает его из личного списка, оставляя запись в отчётности владельца.
- Входящие события Telegram сохраняются вместе с offset. Предоплата обрабатывается отдельно от обычных команд. Платёжные записи повторяются при сбое записи, а прерванные обычные команды требуют проверки результата, поскольку они могут вызывать внешние операции.
- Для оплаты сохраняются срок, сумма, получатель и идентификатор транзакции. Подписка и журнал обновляются атомарно. Возврат по известному зачислению пересчитывает доступ с учётом ручных изменений.
- Реквизиты аккаунтов и прокси передаются через CLI на сервере. В Telegram сводка использует только статусы и идентификаторы. Для операций с общей очередью публикаций и общими материалами требуется доступ владельца.

Подробности полей и прав приведены в [Tokora OpenAPI](tokora-openapi.json).
